# Human Pattern Dreaming

## Personal-understanding loop

Collect evidence → calculate → synthesize → explain → receive feedback → identify contradictions → propose pattern updates → obtain approval → create a versioned profile update.

## Required protections

- Preserve immutable user evidence.
- Distinguish user statements, deterministic calculations, system inferences, and user-confirmed inferences.
- Never use a generated conclusion as self-supporting evidence.
- Show supporting and contradictory evidence.
- Use conditional synthesis when evidence supports multiple interpretations.
- Use Inquiry when resolution is unknown; do not force certainty.
- Require human approval for sensitive conclusions and meaningful profile updates.
- Isolate all evidence and derived memory by user and organization.
- Preserve complete version and supersession history.
- Never automatically modify global or constitutional methodology.

A proposal states evidence IDs, pattern status, confidence and decay rule, contradiction handling, sensitivity, explanation text, requested approval, and rollback target. Feedback is new evidence, not permission to rewrite earlier evidence.

Use `schemas/pattern-ledger.schema.json`, `schemas/dream-proposal.schema.json`, and `templates/dream-review.md`.
