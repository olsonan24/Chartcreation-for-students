# Human Approval Gates

| Gate | Required before | Minimum evidence |
| --- | --- | --- |
| Plan Gate | Meaningful architecture, behavior, intelligence, security, or scope commitment | Feature spec, target, risks, ownership, acceptance, proposed analytics |
| Code Gate | Integrating meaningful implementation changes | Diff, tests, formula/security/intelligence impact, unresolved risks |
| Release Gate | Production mutation or user exposure | Immutable commit, environment proof, reviews, rollback plan, approvals |
| Dream Gate | Applying meaningful Dream or methodology proposals | Evidence lineage, before/after, contradictions, sensitivity, reversibility |

Approval is explicit, scoped, attributable, timestamped, and bound to an artifact version. Silence, a passing test, agent confidence, or a prior approval for another version is not approval.

Mechanically safe and reversible Development Dream maintenance may be auto-applied only under a pre-approved policy that enumerates the exact operation and proof. Formula, constitutional, security, personal-profile, and production changes are never included in that exception.

Rejection records the reason, conditions for reconsideration, and related evidence as negative knowledge. A material artifact change invalidates the prior approval and reopens the applicable gate.
