# Aionis Timeline Formula

An installable timeline chart creator for phone and desktop web browsers.

This repository is the complete public source package for the student-facing application. It includes the responsive web/PWA code, approved formula engine, Supabase authentication and private account persistence, tests, artwork, deployment configuration, project documentation, portable AI chart-building skill, and recovered source-code reference. The private owner console is maintained outside this repository and is never included in the student build.

## Features

- Exact port of the original name, birth-date, pinnacle, challenge, essence, personal-year, calendar-year, and monthly calculations
- Individual timeline charts and multi-chart comparisons
- Touch-friendly phone layout with larger-screen support
- Email/password Supabase authentication with persistent browser sessions
- Private per-user cloud records protected by Postgres Row Level Security
- Consent-based import of older `pass7-mobile-clients-v1` browser records
- Install-to-home-screen PWA shell and static-asset caching
- One-page A4 browser printing and PDF export

## Local setup

Requirements: Node.js 22.13–24, npm, Docker Desktop for local Supabase verification, and Supabase CLI access for linked-project operations.

```bash
npm ci
npx supabase start
```

Create an uncommitted `.env.local` from `.env.example` and use the local API URL and publishable key shown by `npx supabase status`. Never use the local secret key or a hosted service-role key.

```text
VITE_SUPABASE_URL=http://127.0.0.1:55321
VITE_SUPABASE_PUBLISHABLE_KEY=<local publishable key>
```

Then run:

```bash
npm run dev -- --host 0.0.0.0 --port 4173
npm run lint
npm test
```

Open `http://localhost:4173`. `npm test` verifies the locked formula hash and fixtures, authentication/data boundaries, mapping and import behavior, builds the production PWA, and checks the rendered structure.

For an authenticated production-preview phone/PWA/print proof, build with local Supabase variables, run `npm run preview -- --host 127.0.0.1 --port 4175`, then provide a disposable test account:

```powershell
$env:E2E_BASE_URL = "http://127.0.0.1:4175"
$env:E2E_EMAIL = "<disposable test email>"
$env:E2E_PASSWORD = "<test password>"
$env:E2E_SIGN_UP = "1"
npm run test:print-proof
```

The proof creates a minimal test person only when the account is empty and writes `output/pdf/supabase-auth-print-proof.pdf`.

## Supabase schema workflow

The committed migrations under `supabase/migrations/` define `public.people`, its updated-at trigger, explicit Data API grants, and four owner-only RLS policies. The database stores only full birth name, called name, DOB, ownership, and timestamps. Charts and timeline rows are always regenerated by `lib/numerology.ts`.

Local verification:

```bash
npx supabase db lint --local --level warning
npm run test:db
npm run supabase:types:local
```

Linked-project workflow after inspecting the existing remote schema:

```bash
npx supabase migration list --linked
npx supabase db push --linked --dry-run
npx supabase db push --linked
npm run supabase:types
```

Never reset a hosted database. Review the generated type diff and rerun RLS tests whenever the data model changes.

## Vercel deployment

Import `olsonan24/Chartcreation-for-students` into Vercel. The repository is configured for:

- Framework preset: **Vite**
- Root directory: `.`
- Install command: `npm ci`
- Build command: `npm run build`
- Output directory: `dist`

Add these browser-safe variables to both Production and Preview:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_PUBLISHABLE_KEY`

Do not add a Supabase secret or service-role key. The committed `vercel.json` supplies the SPA fallback and service-worker cache headers.

## Persistence, privacy, and offline behavior

Signed-in records are saved to the user's Supabase account. The application derives ownership from the authenticated session, and Postgres RLS independently restricts every select, insert, update, and delete to `auth.uid()`.

The installable application shell, artwork, scripts, and styles can load from the PWA cache after a complete online visit. Authentication and cloud records require connectivity; this release does not include offline database synchronization.

Older local records are never uploaded automatically. After sign-in, the app detects `pass7-mobile-clients-v1`, reports valid/invalid/duplicate counts, and offers Import or Skip. Import duplicates are defined by normalized lowercase full name, normalized lowercase called name, and ISO DOB. The original local-storage value is left untouched even after success and is never destroyed after a failed or partial import.

Signing out immediately removes the current account's people from the active interface. Chart calculations still run inside the application from the minimal saved source fields.
